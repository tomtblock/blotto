# blotto-randomness

Per-entry class randomness derivation and the cosmetic class draw for Blotto Cup. Framework-agnostic
Rust — no `solana-program` dependency, no floats, no allocations beyond the SHA-256 hasher's internal
buffer. Every draw is a pure deterministic function of its inputs and can be replayed from on-chain
data alone.

## The one thing to understand before reading the code

**The class this crate produces is cosmetic. Nothing in the scoring path reads it.** A Titan's
Strength is worth exactly what a Goblin's is. The drawn class is written to the character pass and
to `Entry.class` for display; that is its entire effect.

The class draw is the only chance element in Blotto Cup, and it confers nothing competitive and
nothing of value. Any change that lets a class influence a battle, a pool, a prize or a ranking
tiebreak is out of bounds for this project (see [`CLAUDE.md`](../../CLAUDE.md) and
[`docs/compliance/SAFEGUARDS.md`](../../docs/compliance/SAFEGUARDS.md)).

## What this crate is

Class resolution happens in two steps: derive a 32-byte digest from on-chain inputs, then draw a
class from the pool's remaining counter bag. Both are here, called from the program's `register`
instruction via byte arrays at the boundary (`Pubkey::to_bytes()`).

```rust
pub fn derive_class_randomness(
    vrf_seed: &[u8; 32],
    slot_hash: &[u8; 32],
    entry_index: u16,
    pool_pubkey: &[u8; 32],
    player_pubkey: &[u8; 32],
) -> [u8; 32]
```

SHA-256 over the five inputs concatenated in fixed order — **130 bytes** per entry:

```
vrf_seed(32) ‖ slot_hash(32) ‖ entry_index(2, LE) ‖ pool_pubkey(32) ‖ player_pubkey(32)
```

`vrf_seed` is the Switchboard On-Demand result recorded for the pool (`PoolVrfSeeded`); `slot_hash`
is a delayed `SlotHashes` entry, delayed so the executing validator has no influence over it;
`entry_index` is the pool's seat counter; `pool_pubkey` separates pools; `player_pubkey` binds the
digest to the entrant.

```rust
pub fn weighted_class_draw(rng_bytes: &[u8; 32], class_counters: &[u16; 5]) -> usize
```

A draw without replacement over the five classes `[Goblin, Knight, Wizard, Dragon, Titan]`
(`CLASS_NAMES`), whose bag starts at `LAUNCH_CLASS_COUNTERS = [38, 15, 7, 3, 1]` (sum 64 = one
pool's seats). The first 8 bytes of `rng_bytes` decode as a little-endian `u64`, reduced modulo the
bag's total to land in `[0, total)`, and a cumulative walk returns the class index. Counters are read
but never mutated — the caller decrements.

The argument is named `class_counters`; `CONTRIBUTING.md` → "The language gate" explains why.

## How the program uses it

`programs/blotto_cup/src/instructions/register.rs`:

```rust
let digest = derive_class_randomness(
    &ctx.accounts.pool.vrf_seed,
    &slot_hash,               // delayed SlotHashes entry
    index,                    // pool.entrants: the seat this entry takes
    &pool_key.to_bytes(),
    &player_key.to_bytes(),
);
let class_idx = weighted_class_draw(&digest, &ctx.accounts.pool.class_counters);
ctx.accounts.pool.class_counters[class_idx] -= 1;   // the caller's contract
```

The class is then written to `Entry.class` and the pass and emitted in `EntryRegistered`, and read
nowhere else. The program's `LAUNCH_CLASS_COUNTERS` (`constants.rs`) is checked against this
crate's copy and the Python fixtures by `class_counter_mirrors_hold`, and against the TypeScript
replay in `backend/class-digest` by `scripts/check-mirrors.py` in CI.

## Design properties

### One endianness rule

Little-endian throughout: `u16::to_le_bytes()` for `entry_index`, and the first 8 bytes of
`rng_bytes` read as a little-endian `u64` — matching Borsh's integer encoding. Callers pass the
typed `u16` and let this crate encode it; never hand-encode the bytes at the call site.

### Modulo bias is accepted

`u64 % total` biases toward residues below `2^64 mod total`. With `total ≤ 64` that bias is on the
order of 1 in 2^58. It is accepted for two reasons: rejection sampling would complicate replay (a
replayer would have to reproduce the retry count), and the class confers nothing, so even a
measurable bias would move nothing a player could win. Single-pass determinism wins.

### State and math are separated

`weighted_class_draw` reads `class_counters` through a shared reference and never mutates it. The
caller owns the decrement, alongside the other state writes that filling a seat triggers. Keeping
the math pure makes it testable, replayable and reusable.

### No floats, no allocations

All intermediates are fixed-size byte arrays, `u16`, `u32` or `u64` — in the tests too, where the
convergence tolerance is expressed in count units rather than as a float ratio.

## Test vectors are generated by Python, and the generator is committed

`fixtures/vectors.json` holds three `derive` vectors and five `draw` vectors — one per class. Every
expected digest is computed by `fixtures/gen_vectors.py` using Python's `hashlib`, **not** by this
crate. A vector captured from the crate's own output would prove only that it agrees with itself.

```bash
python3 fixtures/gen_vectors.py --write    # regenerate fixtures/vectors.json
python3 fixtures/gen_vectors.py            # print to stdout, to diff against the committed file
```

The script uses only the Python standard library. The Rust side embeds the JSON with
`include_str!`, so the tests have no runtime file dependency.

## Test coverage

**19 tests, all deterministic.**

Unit tests (16, in `src/lib.rs`):

- *Known vectors* — all three `derive` fixtures and all five `draw` fixtures, plus a check that the
  draw fixtures cover every class exactly once.
- *Canonical stream* — rebuilds the 130-byte input by hand and hashes it directly, so a change to
  input order or index encoding cannot pass even if the fixtures were regenerated to match.
- *Determinism* — repeated calls against fixed inputs match exactly.
- *Avalanche* — a single-bit flip in **each of the five** inputs changes more than 96 of 256 digest
  bits (a loose bound; SHA-256 expects about 128).
- *Two players, same seat* — different players at the same index get different digests.
- *Counters sum to capacity* — 38 + 15 + 7 + 3 + 1 = 64.
- *Edge cases* — a lone-Titan bag returns index 4; a lone-Goblin bag returns index 0; an empty bag
  panics.
- *Property tests* — over random `(class_counters, rng_bytes)` pairs with counters in `0..=64`: the
  index is in `0..5`, the drawn counter is non-zero, and the counters are unchanged by the call.

Integration tests (3, in `tests/properties.rs`):

- *Counters sum to capacity* — asserted here as well, so a divergence between the two files fails.
- *Distribution convergence* — 100,000 deterministic draws, with per-class frequencies within ±2
  percentage points of the counter ratios.
- *Full-pool invariant* — 64 simulated entries with draw → decrement: the bag falls by exactly one
  per entry, ends at `[0; 5]`, draws per class equal the launch bag exactly (one Titan, three
  Dragons, …), and a draw after the pool is full panics.

## Testing

```bash
cargo test -p blotto-randomness
cargo clippy -p blotto-randomness --all-targets -- -D warnings
cargo fmt -p blotto-randomness -- --check
```

The dependencies are pinned exactly (`sha2 = "=0.10.9"`, `proptest = "=1.11.0"`): the hash
implementation sits under an output that is committed on-chain and recomputed by players, so an
upgrade is a separate, tested change.
