The allocations below are **derived from the seeds frozen in `T4.plan.json`** (PR 133, merged 2026-09-16T16:22:00Z, plan sha256 `c74333f022b0…e064`). This file adds no prediction — it renders one that was already fixed, so it reads the same whenever it is generated.

## How to read the state column

| State | Meaning |
|---|---|
| `PENDING` | no entry has landed yet; the intended allocation only |
| `COMMITTED` | the entry landed and the chain holds `sha256(battles ‖ salt)`, which nobody can open yet |
| `VERIFIED` | the pool revealed its secret; the published battles and salt recompute to the hash the chain recorded at entry |

A salt is never printed before its pool reveals: publishing one early would let a guess at that entry's allocation be confirmed, which is the sealing property gone.
